# 正式採用機能まとめ

更新日: 2026-05-09

## 目的

実験的に追加してきた機能を、正式採用済みの機能として整理する。

この文書では、以下の観点で分類する。

- 現在できること
- 関連する画面/API/サービス
- 体験上の価値
- 正式機能として今後決めること
- 整理方針

## 位置づけ

この文書に挙げる機能は、すべて正式採用とする。

元々は実験的に作った機能が多いが、今後は削除候補ではなく、正式機能として仕様、権限、UI、テスト、運用手順を整える対象とする。

コア寄り:

- ワールド/プロジェクト
- キャラクター
- ライブチャット
- 記憶
- Feed
- World News
- おでかけ
- クローゼット

正式採用済み:

- スタジオ
- ポイント
- ライブチャット写真モード
- 所持品/ギフト/親密度報酬

基本方針:

- 既存実装は正式サポート対象とする。
- 未整理のUIやAPIは、削除ではなく仕様整備対象とする。
- 一般ユーザーに制作/管理操作を許すかどうかは、機能ごとに権限を整理する。
- 迷った場合、閲覧/体験は広く、制作/生成/管理はプロジェクト管理権限以上に寄せる。

## 4. ライブチャット写真機能

ライブチャット写真機能は正式機能とする。

### 現在できること

ライブチャットの写真系機能は、大きく2つに分かれる。

1つ目は、ユーザーが明示的に撮影する「撮影モード」。  
2つ目は、会話や場面の流れからAIが撮影候補を出す「シャッターチャンス」。

現在できること:

- セッション中に撮影モードを使う
- 撮影用のproxy messageを生成する
- 写真/ポーズ/構図に応じた画像生成につなげる
- 会話内容からシャッターチャンス候補を生成する
- シャッターチャンスを、会話中の思い出CGや写真イベントのきっかけにできる

### 関連実装

- API: `/api/v1/chat/sessions/<session_id>/photo-mode/shoot`
- Service:
  - `app/services/live_chat_conversation_service.py`
  - `app/services/live_chat_text_support.py`
- JS:
  - `app/static/js/live_chat_photo_mode.js`

### 体験上の価値

撮影モードは、ユーザーが「今この瞬間を撮る」と決める能動的な導線になる。

シャッターチャンスは、キャラクターや会話の流れから「今、撮ったらよさそう」という受動的/提案型の導線になる。

この2つを分けることで、写真機能は単なる画像生成ボタンではなく、会話中の思い出や関係性の変化を残す仕組みになる。

### 正式機能として今後決めること

- 撮影モードを常時表示するか、条件解放にするか
- シャッターチャンスを自動表示するか、控えめな提案にするか
- 撮影画像をFeed/記憶/メールに残すか
- ポーズ指定をどこまでユーザーに任せるか
- シャッターチャンスを無視した場合に、会話や記憶へ影響させるか

### 整理方針

ライブチャットの正式派生機能。

推奨:

- 「撮影モード」と「シャッターチャンス」を分けてライブチャット仕様書に章を作る
- おでかけの思い出CGと同じ画像資産ルールに寄せる
